## 3. 결함 목록

### 차단 (릴리스 전 필수, 2건)

**B-1. `.xtime` 시간 배분 블록이 흐름에서 이탈해 41x32px 원으로 접힌다. 8/8 면, 1280과 390 모두.**
위치 = `~/Workspace/hyunhak-site/assets/exam_page.css` 125~132행.
무엇이 왜 = SELF_CHECK §8 의 「`.xc` 의 `.xtime` 규칙만 `.xa` 로 옮긴다」를 적용하면서 각 규칙 앞에 `:where(body.xa) .xtime,` 를 붙였다. CSS 에서 쉼표는 새 선택자를 시작하므로, 124행(블록 전체 대상)만 의도대로 동작하고 125~132행은 `.cap` `.row` `.row::after` `.row .st` `.bar` 용 선언을 `.xtime` 컨테이너 자신에게 먹인다. 실측 computed = `position:absolute; top:24px; left:16px; width:41px; height:32px; border-radius:50%; box-shadow:inset 0 0 0 2px ink`. 가장 가까운 위치 지정 조상이 `.sheet`(relative)라 블록이 문서 최상단으로 올라가고, 5개 `.row` 는 폭 0(실측 w=0, h=274~1041)이 되어 본문이 1글자씩 세로로 흘러 크럼브, H1, 리드, 앵커 내비, 규격표, 유형 지도 위(y 199~2382, x 111)를 관통한다.
고치는 방향 = 각 행의 첫 선택자를 완전한 형태로 적는다. 예: `:where(body.xa) .xtime .cap,:where(body.xc) .xtime .cap{...}`. 6행 전부 동일 처리.

**B-2. `#method` 핵심 원칙 목록의 본문이 24px 번호 칸으로 떨어져 1글자씩 세로로 깔린다. 8/8 면, 전 항목(4~5개) 100%.**
위치 = 빌더 산출 마크업, 예 `~/Workspace/hyunhak-site/interview/korea-hum.html` 127행 `<ol class="xrules">`. 생성기 = `build_pages.py` 269행 `"method_rules": rules(METHOD_RULES)`.
무엇이 왜 = `.xrules li` 는 `display:grid; grid-template-columns:var(--s4) minmax(0,1fr)` 이다(`exam_page.css` 103행). 빌더는 `<li><b>제목</b> 본문…</li>` 을 내보내 익명 텍스트 런이 세 번째 격자 항목이 되고, 2행 1열(24px)로 배치된다. 실측 li 높이 1,069~1,293px, `.xrules` 전체 4,860~6,637px. 디렉터 정본 `tpl_A.html` 은 `<li><span>본문</span></li>` 로 문장을 1개 자식으로 싸서 이 결함이 없다. SELF_CHECK §6 결함4 에서 이미 잡아 고친 항목의 회귀다.
고치는 방향 = 빌더가 `<li><span><b>제목</b> 본문…</span></li>` 로 문장 전체를 span 1개로 싸도록 `rules()` 를 고친다. `.xlock ul li` 도 같은 계열이므로 함께 확인한다.

### 권고 (차단 아님, 4건)

**W-1. 각주 3번 고아.** 5개 면에서 `.fnlist` 에 3번 정의가 있으나 본문에 `sup.fn` 3 이 없다(표에 1, 2, 4 만 나타나 번호가 건너뛴다). 해당 값에 기호를 달거나 정의를 뺀다.

**W-2. 오픈 예정 면 CTA 중복.** `#plan` 의 「9월 14일 오픈, 공지 보기」 텍스트 링크와 `.xsoon` 띠의 「공지 보기」가 같은 목적지로 약 50px 간격에 이웃한다. 띠 하나로 합친다.

**W-3. `#types` 4열 표의 수동적 여백.** 4열이 6줄로 늘 때 2, 3열 아래가 4줄분 비는 행이 있다(방법론 적용 행). 4열 「기출과 은행」과 「읽는 열쇠」를 2열로 나누거나 3열과 병합한다.

**W-4. `.k` 라벨 자간이 어절 간격을 벌린다.** `letter-spacing:var(--tr-label)` 때문에 「전형별  면접  상세면」, 「그  밖의  문의」처럼 어절이 떨어져 읽힌다. 라벨에 `word-spacing` 보정을 주거나 자간을 낮춘다.

다만 Δ 의 원인은 셀프 후함이 아니라 **채점 대상 불일치**다. 디렉터는 시안(`tpl_*.html`, 임시 문안)을 쟀고 critic 은 실데이터 빌드를 쟀다. 두 차단 결함 모두 시안에는 없고 시안 이후 두 자리(CSS 이관, 빌더 마크업)에서 들어왔다. 셀프 편향 플래그는 **켜지 않는다**. 누적 3회 규칙에도 계상하지 않는다.

**16뿌리 적발 = 0/16.** 디렉터 판정 0/16 을 실데이터 산출에서 재확인했다. 그라디언트, 생성 이미지, Inter, Space Grotesk, 균등 카드 격자(A안이라 비해당), 발광, 지브라 표 모두 0.

## 5. 승계 세션에 남기는 검출기 권고

두 결함 모두 메인 세션이 돌린 검출기(가로 넘침, 표 셀 초과, 히트박스 44, 금지 문자, 자리표, 페이지 오류)의 사각이었다. 전건 초록이면서 면의 절반이 깨져 있었다. 아래 2개를 상주시키면 결정론으로 잡힌다.

1. **면 길이 기준선 대조.** 디렉터 실측 A안 1280 판매중 = 6,567px. 실빌드 korea-hum 1280 = 14,962px, 2.28배. 시안 대비 1.5배를 넘으면 빌드를 세운다.
2. **세로 깔림 오라클 재사용.** SELF_CHECK §6 표에 이미 있는 검출기(문장 칸을 20px 로 주입, 0 → 3 으로 살아있음 확인)를 실빌드 산출에 돌린다. 줄 수 대 글자 수 비로 재므로 글리프 폭과 무관하다. 이 검출기는 만들어졌으나 실데이터 8면에는 한 번도 돌지 않았다.
3. **`getBoundingClientRect` 겹침 검사 추가.** 절대배치 이탈은 가로 넘침 검사로 원리적으로 안 잡힌다. `main` 안 형제 블록의 세로 구간 교차와 `position:absolute` 이면서 조상이 `.page` 가 아닌 요소를 센다.

수리 후 **재채점 필수**. 두 차단 결함만 닫히면 렌즈1, 3, 4, 6, 8 이 동시에 오르므로 총점 구간이 바뀐다.

## 2. 공통점 (N≥3)

1. **섹션 순서는 이야기 순서**: 훅(메인 비주얼) → 공감과 문제 정의 → 해결(구성과 특징) → 사용법 → 신뢰(만든 사람, 근거, 후기) → 구매 행동. 6~13단계, 출처 6건 일치.
2. **배경 명암 교대**: 짙은 판과 밝은 판을 번갈아 스크롤 박자를 만든다 (1, 5, 7).
3. **서체와 색 절제**: 헤드 1종 + 본문 1종, 색 3가지 안팎 (1, 5, 7).
4. **이미지는 분위기 전달용, 텍스트는 조판층**: 이미지 안에 글자를 넣지 않고 HTML이 글자를 얹는다. 헤드라인 여백을 프롬프트에 예약 (1, 2, 5, 6).
5. **키비주얼 1장을 먼저 확정**하고 나머지 이미지의 톤을 거기에 맞춘다 (1, 5).
6. **산출은 HTML/CSS가 원천**, 필요 시 Playwright로 PNG를 뽑아 수직 결합 (2, 6). PSD는 외주 운영 목적(1).
7. **첫 초안은 밋밋**, 3회 안팎 반복 수정이 표준 (2, 7).

## 3. 본 작업 적용

- 구조 = SB7 + 프라이탁 아크 (v10 09 내러티브 아크 SSOT와 합치): 문제(같은 이름, 다른 세 시험) → 안내자(한 사람 같은 기준 편집) → 계획(5부 = 이 책을 쓰는 법 5단계) → 절정 4부(50~65% 지점) → 실패와 성공 대비 → 단일 CTA.
- 명암 박자 = 楮紙 판 기본, 玄墨 반전 판을 문제 섹션과 마무리 CTA 두 곳에만.
- 서체 = 사이트 v3 규범 그대로(Pretendard 800 표제, 16px 본문, JetBrains Mono 계기값, 세리프는 인용만). 색 = 玄墨, 楮紙, 朱印 점 + 표지의 남색은 실물 사진으로만 들어온다.
- 이미지 = gpt_image_2, 글자 0, 사람 0, 한지와 먹과 남색 소책자 물성 언어. 키비주얼(히어로) 3안 먼저, 채택안 톤에 섹션 7장을 맞춘다. 헤드라인 여백을 프롬프트에 예약.
- 산출 = 독립 HTML 1본(data URI 자족). PNG 수직 결합본은 필요 시 Playwright 전체 캡처로.
- 반복 = critic 채점 후 1회 이상 수정.

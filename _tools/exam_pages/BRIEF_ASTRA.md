# 집필 의뢰: 전형별 면접 출제 유형·풀이법 상세면 본문 (제2 집필 레그, gpt-6-astra)

너는 현학적 연구소(hyunhak.com, 대입 면접 콘텐츠) 상세면 8본 가운데 **한 전형**의 본문을 쓴다. 코드는 stdin 마지막 줄 `CODE=<code>` 로 온다. 파일을 고치거나 만들지 마라. 답은 **JSON 하나**만 출력한다(앞뒤 설명·코드펜스 금지).

## 읽을 것 (전부 읽고 시작한다. 읽지 않은 원천의 수치는 쓰지 않는다)
1. 사실 원장 = `hyunhak-site/_tools/exam_pages/facts/<code>.json` (spec = 요강 실측값, bank = 우리 은행 세트 전수 요약, pastexam = 2026 기출 해설 세트 요약). **숫자는 이 파일의 값만 쓴다.** 여기 없는 수치(연도별 경쟁률, 합격선, 통계 비율, 학생 수)는 한 글자도 쓰지 않는다.
2. 은행 스펙 = 코드별
   - yonsei-hum / yonsei-sci: `yonsei_interview_bank_2027/spec/SPEC_v1.md` (§1 출제 원칙, §3 문항 구조·발문 유형 6종·계열별 구조 불변식)
   - yonsei-intl: `yonsei_intl_interview_bank_2027/spec/SPEC_v1.md` (§2 구조 불변식, §3 제시문 역할, §5 난이도 4축, §8 해설 구조)
   - yonsei-mirae: `yonsei_mirae_interview_bank_2027/spec/SPEC_v1.md` (§0 전형·단위, §2 유형 A~G 구조 불변식, §3 분량) + `spec/SPEC_v1_ERRATA_20260909.md` + `spec/Q3_RULES_2027.md`
   - korea-hum / korea-sci: `korea_interview_bank_2027/spec/SPEC_v1.md` (§1 출제 원칙, §2-1 세트 유형 3종, §3 유형별 체인 불변식) + `spec/PRACTICE_META_v1.md` (§1 F1~F5, §2 R21 5단계, §3 두 트랙)
   - korea-eq-hum / korea-eq-sci: 은행이 없다. 원천 = `hyunhak-site/_tools/exam_pages/src/korea_2026_eq_cards_raw.txt`(2026 고른기회 문항카드 인문·자연 원문, 선행학습영향평가 보고서), `korea_2025_eq_cards_raw.txt`, `korea_2024_eq_cards_raw.txt` + 계열적합 스펙(`korea_interview_bank_2027/spec/SPEC_v1.md`, `PRACTICE_META_v1.md`)을 "같은 대학 같은 출제진의 짧은 판(준비 12분·답변 6분)"으로 읽는다. 고른기회 고유 사실(3개년 문항 구성, 제시문 수, 발문 꼴, 교과 근거)은 원문에서만 가져오고, 계열적합에서 가져온 절차는 "계열적합 판을 12분에 맞춘 것"이라고 문면에 밝힌다.
3. 예시 문항용 세트 1개 = facts 의 `bank.sets` 중 `difficulty` 가 "하"인 첫 세트(없으면 첫 세트)의 `file` 을 열어 제시문·질문·(있으면) explanation 을 읽는다. 고른기회는 2026 문항카드(인문 또는 자연)를 쓴다.
4. 문체 규범 = 아래 §문체.

## 무엇을 쓰나 (독자 = 고3·재수생·학부모, 검색과 답변엔진에서 들어온다)
"이 전형은 어떤 문제가 나오고 어떻게 푸는가"를 정확하게 설명하되 **전부를 주지 않는다**. 공개 층 = 규격, 유형, 풀이 절차의 골격과 원칙, 예시 문항 1세트의 풀이 골격, 흔한 실수, 준비 순서. 비공개 층(쓰지 않는다) = 모범답안 전문, 루브릭 항목 나열, 세트별 전략, 시간 배분의 세부 초 단위 전부, 함정 목록 전체, 해설 강의 대본. 비공개 층은 "스튜디오 리포트와 해설 인강에서" 라는 경계 문장 한 줄로만 가리킨다.

각 필드의 길이 상한을 지킨다. 지면은 한 화면에 한 생각이다.

## 출력 JSON 스키마 (키 이름·순서 고정, 값은 전부 한국어 문자열 또는 배열)
```
{
 "code": "<code>",
 "h1": "<대학> <전형명> 면접, 출제 유형과 풀이법 (2027)",           // 40자 이내
 "title_tag": "…",                                                    // 60자 이내. 검색 제목. 앞에 핵심 검색어(대학명+전형명+면접)
 "meta_description": "…",                                            // 120~155자. 답변엔진용 요약. 숫자는 facts 값만
 "keywords": ["…", …],                                                // 10~15개. 실제 검색어 꼴(예: "연세대 활동우수형 면접 기출", "고려대 계열적합 제시문 면접 준비"). 대학 약칭·정식명 둘 다
 "lead": ["문장1", "문장2"],                                          // 각 60자 이내. 문장1 = 형태·제시문 수·준비·답변·질문 수. 문장2 = 이 면이 주는 것
 "answer_box": "…",                                                   // 2~3문장 200자 이내. "…전형 면접은 …입니다. …" 답변엔진이 그대로 인용할 문단
 "spec_notes": ["…", "…"],                                            // 규격표 아래 각주 1~3개. 출처를 문장 안에 밝힌다
 "types": [                                                           // 3~5개. 3개년 기출과 우리 은행에서 실재하는 유형만
   {"name": "…", "definition": "…", "frequency_note": "…", "prompt_shape": "…", "reading_key": "…"}
   // definition 80자 이내 / frequency_note = 기출·은행 빈도 문장(facts 값만, 예: "은행 30세트 중 15세트") / prompt_shape = 대표 발문 꼴 1개 (은행·기출 발문 verbatim 또는 꼴 서술) / reading_key = 이 유형을 읽는 열쇠 1문장(공개 층까지만)
 ],
 "method": {
   "principles": [{"title": "…", "body": "…"}],                       // 3~5개. title 20자, body 120자 이내
   "timeline": [{"stage": "…", "seconds": "…", "doing": "…"}],        // 4~6단계. seconds 는 facts 의 prep_sec 합과 맞는 대략 값("약 180초" 꼴 허용), 세부 배분 전부를 주지 않는다
   "boundary": "…"                                                    // 1문장. 여기서부터 비공개
 },
 "sample": {
   "set_id": "…", "doc_head": "…",                                     // 은행 세트 id / 시험지 머리 라벨(예: "2027 계열적합전형 인문 모의 세트 01")
   "passages": [{"tag": "(가)", "excerpt": "…"}],                      // 2~4편. 우리 은행 세트면 원문 2~4문장 verbatim. 고른기회(대학 문항카드)는 제시문을 1~2문장으로 요약하고 직접 인용은 한 문장 이내
   "questions": ["…"],                                                // 문항 전부 verbatim
   "steps": [{"title": "…", "body": "…"}],                            // 3~4단계. 마지막 단계 body 는 "…은 스튜디오 리포트에서 …" 경계 문장
   "first_sentence": "…",                                             // 문항 1 답변의 첫 문장 예시 1개(결론 선언 꼴). 모범답안이 아니라 첫 문장 하나
   "trap": "…",                                                       // 이 세트에서 갈리는 함정 1개 (2문장 이내)
   "source_note": "…"                                                 // 출처 문장(우리 은행 자작 / 고려대 선행학습영향평가 보고서 2026 문항카드)
 },
 "pitfalls": [{"title": "…", "body": "…"}],                          // 정확히 3개. body 100자 이내
 "plan": [{"step": "1", "title": "…", "body": "…"}],                 // 정확히 4단계. 우리 자료(스튜디오 세트 수·해설 인강 편수·2026 기출 해설·가이드북)는 facts 값이 있을 때만 숫자로, 없으면 이름만. 오픈 예정 전형은 "9월 14일 오픈" 문장을 4단계 중 한 곳에
 "faq": [{"q": "…", "a": "…"}],                                      // 정확히 5개. q 는 실제 검색 질문 꼴(…인가요 / …나요), a 는 2~3문장 160자 이내, 첫 문장이 답
 "siblings_note": "…",                                                // 형제 전형과의 차이 1문장 (예: 활동우수 인문 대 자연, 계열적합 대 고른기회)
 "offline_note": "…"                                                  // 오프라인 수업 문의 문장 1개. 전화번호 070-8098-0671 을 그대로 넣는다

```

## 문체 (위반 1건 = 반려)
- 합쇼체("…입니다", "…합니다")로 쓴다. 명령형("…하라")과 반말 금지.
- 은유·비유·대구·경구·격언 금지. 사실 진술과 절차만.
- 가운뎃점(·)과 줄표(—) 금지. 나열은 쉼표, 병기는 "와/과".
- 최상급·감탄부호·"합격"·"보장"·"1위"·"최고"·"단 하루"·"지금 아니면" 금지. 경쟁률·합격선·점수대 언급 금지.
- 문장 하나에 생각 하나. 40자 안팎. 접속 부사로 시작하지 않는다.
- 숫자는 facts 파일 값만. 없는 숫자는 쓰지 않는다. 추정 수치 금지.
- 대학 공식 명칭을 첫 등장에 정식으로("연세대학교 학생부종합 활동우수형"), 이후 약칭.
- 학생 개인정보·실명·특정 학교명(고교) 0.

## 자기검사 (출력 전에 스스로 확인, 통과 못 하면 고쳐서 낸다)
1. JSON 이 파싱된다. 키 이름·개수 상한이 맞다.
2. 본문에 나온 모든 숫자(초, 분, 편, 세트, 문항, %)가 facts 파일에 있다.
3. 모범답안 전문·루브릭 나열·세부 초 배분 전부가 없다.
4. 금지어 0, 가운뎃점 0, 줄표 0, 명령형 0.
5. 예시 문항의 발문이 세트 파일과 글자까지 같다.

출력 = JSON 한 덩어리만.
